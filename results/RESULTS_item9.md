# Item 9 — XPU 上纯残差架构的端到端小规模训练（闭环验证）

日期：2026-11-26　设备：Intel Arc iGPU（Meteor Lake，112 EU）+ Core Ultra

## 1. 这次跑的内容

```
python scripts/run_closed_loop.py \
    --arch res-s --L 8 --q 3 --rounds 10 --steps-per-round 200 \
    --resample-every 15 --scan-batch 1024 \
    --beta 0.4 --beta-start 0.15 --optimizer muon --gate-mode holdout_nll \
    --out-dir runs/item9_res_s
```

- **架构**：`res-s`（纯残差，4 个 3×3 残差块，48 通道，**无注意力**）——按你的要求"暂时不用 nbt+transformer"
- **优化器**：Muon（矩阵参数）+ AdamW（其余）
- **门控**：留出集 proper scoring rule（λ=0.75 遮蔽位交叉熵），留出集由 C++ Swendsen-Wang 生成，**只用于门控、从不参与训练**
- 总计约 **22 分钟**，0.168 M 参数

## 3. 为什么这次收敛了（前一轮失败的三个原因）

| 症状 | 根因 | 修复 |
|---|---|---|
| 损失恒为 0 | `weights` 被转成 `x.dtype`，而 x 是 **int64** → 权重截断为 0 | 保持 float |
| 损失"改善"但 NLL 每轮变差 | `ce` 已是 `-log p`，外层又多一个负号 → 在**最大化**交叉熵 | 去掉多余负号 |
| 门控分数每轮完全一致 | 门控在 bf16 下评估，NLL 被量化到 0.0078 的网格上，看不到 0.1% 的改进 | 用 float32 从 raw logits 重算 |
| ESS≈0.008，训练只见过 5 个样本 | **重要性权重退化**：β 从目标值直接起步，`exp(-βH)` 跨度过大 | **β 从 0.15 起步退火到 0.4**，ESS 全程维持在 0.13–0.40 |

关键教训：**低温下自生成样本的重要性权重会退化**（一个样本吃掉全部权重），
所以闭环必须从"热的、权重不死"的区域起步，再逐步降温——这正是原论文
`--use_anneal` 的作用，我第一版的闭环漏了它。

## 4. 门控的价值验证

同一套门控在两轮失败实验里**拒绝了所有候选**（5/6、0/6），在训练器修好后**接受了全部候选**（10/10）。
它拒绝的正是"训练损失在降、但留出集似然在变差"的假进步——这是单看训练损失绝对发现不了的。

## 5. 与论文原始配置的差异（必须说明）

| | 本实验 | 原论文 |
|---|---|---|
| L | 8（D=64） | 16 / 24（D=256 / 576） |
| 温度 | β 0.15→0.4（**高于临界温度**，弱关联） | β=1.005（临界）/1.2（有序） |
| 轮数×步数 | 10×200 | 50000 epochs |
| 硬件 | Intel Arc iGPU（共享内存） | A100 |

所以这次是**"闭环可行"的工程证明**，不是"复现论文数值"。
在 β→1.2 的有序相上要复现论文效果，需要更大的 batch、更长的训练，以及更细的退火日程——
按 Item 1 的实测，CPU 端数据生成只需 ~1 秒/10 万样本，算力瓶颈完全在训练侧。
